# Spec: safer Caps Lock dual-role remap

## Objective

Keep the existing Windows behavior while preventing stray Escape events and lost or stuck Ctrl state. Tapping Caps Lock sends Escape, holding it acts as left Ctrl, and pressing bare physical Escape toggles Caps Lock.

## Requirements and acceptance criteria

### REQ-001: deterministic dual-role state

- AC-001: Given Caps Lock is up, when it is pressed once, the script enters held state and requests one left-Ctrl down event.
- AC-002: Given Caps Lock is already held, when a repeated down event arrives, the original press time and usage state do not reset.
- AC-003: Given no other input occurred, when Caps Lock is released within 250 ms, the script releases left Ctrl and sends Escape.
- AC-004: Given another keyboard or mouse input occurred while Caps Lock was held, when Caps Lock is released, the script releases left Ctrl without sending Escape.
- AC-005: Given Caps Lock was held longer than 250 ms, when released, the script releases left Ctrl without sending Escape.
- AC-006: Elapsed-time calculation remains correct across the 32-bit A_TickCount rollover.

### REQ-002: robust modifier lifecycle

- AC-007: One gesture handler owns Caps Lock from press through release, uses remap-grade `LCtrl DownR` semantics, and releases its simulated left Ctrl during normal exit/reload. A physical hold is polled from AutoHotkey's hook-tracked physical state, because Win32 async state never sees a key-down that the hook blocked (measured 2026-11-16: it reads up for the whole hold, which ended every gesture at once). A press injected by other software has no physical state and is followed through its key-up event.
- AC-007a: If an elevated window or the secure desktop takes over during a hold, the gesture ends without Escape and the simulated left Ctrl is released as soon as input can be sent again.
- AC-008: Releasing a physical left Ctrl while Caps Lock remains held causes the script to reassert the remapped left Ctrl.
- AC-009: Releasing Caps Lock uses AutoHotkey's physical-only left-Ctrl state—not Win32 async state, which includes injected Ctrl—so it releases script-owned Ctrl without forcing a physically held modifier logically up.

### REQ-003: complete input detection

- AC-010: All physical keyboard keys except Caps Lock, including keys already held when Caps Lock is pressed, are checked through Win32 async state and mark the current press as used without blocking the key.
- AC-010a: In windows listed in `g_TapWhileHoldingWindows` (games; ships with `ahk_exe Wow.exe`), input already held when Caps Lock is pressed does not mark the press as used, and auto-repeat of those held keys is ignored, so a tap still sends Escape while moving or steering. New key or mouse presses during the hold still mark it used.
- AC-011: Primary, secondary, middle, extra mouse buttons, and vertical/horizontal wheel input mark the current press as used without blocking the input.

### REQ-004: Caps Lock toggle

- AC-012: Bare physical Escape is blocked from the active application and exclusively toggles Caps Lock without relying on `A_PriorKey`.
- AC-013: Escape generated by the Caps Lock tap does not recursively invoke the physical-Escape hotkey.

### REQ-005: portable verification and deployment

- AC-014: Running the standalone script with `--self-test` performs no hotkey installation; `--verify-hotkeys` registers names disabled so it cannot intercept input beside a live remap; both modes exit immediately.
- AC-015: The tracked and Startup copies are byte-identical, parse under installed AutoHotkey v2, and the Startup copy runs after deployment.

## Non-goals

- Bypassing Windows UIPI, secure-desktop restrictions, anti-cheat, or raw-input limitations.
- Elevating the script.
- Solving double-remapping when separate copies run on both sides of an RDP session.

## tech stack and commands

- AutoHotkey v2.0.26, one standalone `.ahk` file.
- Test: `python tests/test_capslock_ctrl_escape.py`
- Test deployed Startup copy and live process: `python tests/test_capslock_ctrl_escape.py --deployment`
- Syntax/runtime check: the same test invokes the real script with `--self-test` using `AutoHotkey64.exe`; set `AUTOHOTKEY_EXE` to test another installation.
- Deployment verification: byte-compare the tracked and Startup scripts and query the live AutoHotkey process command line.

## project structure

- `CapsLockCtrlEscape.ahk`: portable source and built-in state tests.
- `tests/test_capslock_ctrl_escape.py`: command-line self-test runner.
- `.hermes/specs/capslock-dual-role/`: specification.
- `.hermes/plans/`: implementation plan.

## boundaries

- Always: preserve tap-Escape, hold-Ctrl, and exclusive bare-Escape Caps Lock toggle behavior; test before deployment; keep Startup and source identical.
- Ask first: elevation, registry remapping, or a different Caps Lock toggle gesture.
- Never: send test keystrokes into the user's active applications or overwrite unrelated repository work.
